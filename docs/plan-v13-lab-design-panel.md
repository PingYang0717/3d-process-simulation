## 0. 一句話

設計區從「一張 112 px 的縮圖＋一堆折起來的欄位＋只能加不能改的預設」變成：一張**可換視角、可拖切片、用變數自己的顏色標出它改哪裡**的預覽；每個變數是一句話「對 **Poly-Si 1** 的［圓頭半徑 ▾］· 現在是方角」，**要改什麼在卡片上直接換**、軸／面／錨點就在卡片裡；要試的值每顆 chip **點一下就能改**，預設只是把「起始／間距／個數」三格填好；組合表每一列都有狀態（可產生／對照組／未試算＋原因／無效原因）。欄寬與預覽高度都能拖。

## 2. 查證：現況到底怎麼回事

在 commit 2bd7573 上 `npm run dev`＋Playwright（headless Chromium）照使用者的路徑走：載範例 → 選 Poly-Si 1 → 實驗頁 → 加一個變數（預設圓頭半徑）。

- **視角**（P1）：`StructurePicker.StructThumb` 用 `autoAxis(box)`：外框最長的軸當法線。poly 沿 x 最長 → YZ 截面，看到的是 poly 的「端面」：一個 24×42 的矩形，看不出是哪一根、也看不出圓角會長在哪。`structThumbRGBA` 只有「選到的藍、其他淡化、FacePicker 滑過的那條邊」三種標記，變數本身沒有畫在圖上。`size` 固定 112。
- **預設**（P2）：`NewFactorForm` 的「操作」下拉只在新增時出現；`FactorCard` 沒有換操作的入口。`LevelsEditor.add()` 是 `uniqSorted([...levels, ...vs])`：預設按鈕永遠是「加進去」，chip 是 antd `Tag closable`，沒有編輯。
- **難懂**（P3）：`FactorCard` 把 `axis`／`anchor`／`dir`／`policy` 放進 `Collapse ghost`「設定」；水平列的標籤是「水平」「預設」，絕對／相對 Segmented 只有 tooltip。
- **範圍太大**（P4）：`ComboTable.useTrials` → `previewIn(start, { op, cap: 3_000_000, … })`；`workerCore.preview` → `previewOp(…, cap)` 在 `boxVoxels(box) > cap` 時回 `null` → `{ none: true }` → 表格印「範圍太大」。圓頭的 op 範圍＝整個結構外框。×1 範例 poly 144×42×24＝0.15 M（有數字）、×3 範例 432×126×72＝3.92 M（全部「範圍太大」）。產生走 `replay`，沒有這個上限。
- **盤面**（P6）：`.lab-design { width: 400px }`，只有 `collapsed` 一個狀態；編輯頁有 `Resizer`（左欄 180～420、右欄 300～560）但寫在 `index.tsx` 裡，實驗頁沒用。

## 3. 目標與驗收方式

- **看得出改哪裡**：Poly-Si 1 加「圓頭半徑」後，預覽切到 XY 看得到三根 poly 的截面、頂端兩角有該變數顏色的圓弧與標籤；再加「對稱 CD（沿 z）」，XY 視角下框線變虛線並出現提示「沿 z，垂直於這個切面（換 XZ 或 YZ 看）」。切片滑桿範圍＝結構外框在法線上的範圍。「在 3D 看」→ 編輯頁、相機對準這個結構的外框。
- **改得動**：卡片上的［操作 ▾］換成「對稱 CD」後，結構與名稱不變、水平換成新操作的第一組預設；點任一顆 chip 可以改數字、確定後組合表跟著變；預設按鈕把「起始／間距／個數」填好並取代現有的值；三格改了再按「套用」。
- **說得清楚**：組合表每一列的狀態欄只會是「✓ 可產生」「對照組」「可產生 · 未試算」（tooltip 寫上限與「產生不受影響」）或無效原因（紅）；表尾在有未試算或無效時各一句總結。×3 範例的 poly 圓頭（3.92 M 格）在 8 M 上限內會有數字。
- **盤面**：設計欄中間那條線可拖（360～760 px，鍵盤方向鍵也行）、預覽底下那條線可拖（140～560 px）；重新整理後都還在；欄寬拖了預覽跟著填滿。
- **不退步**：`npm run typecheck`、`npm test`（248）、`npm run build`、`scripts/e2e/m12.cjs`（選擇器跟著改）全過；產生出來的 split 的 ops／名稱／manifest 和改前逐位元組相同（設計區只是輸入介面）。

## 4. 原則、不做的事

不變：Factor／水平只是標註、Op 是唯一真相；實驗頁沒有 WebGL（3D 只在編輯頁掛一個，plan v12 §5.4）；試算走 Worker、一次一個、可取消。

新增三條：

- **圖上標、不靠文字猜**：變數會動到哪裡，一律畫在預覽上（用變數卡的顏色），畫不出來（垂直於切面）就明說要換哪個視角。
- **能改的地方就地改**：操作、軸、面、值，都在卡片上改，不走「刪掉重加」。
- **沒估到要說為什麼**：任何被略過的估計都要寫原因與影響範圍（「只是估計，產生不受影響」）。

不做：預覽做成可旋轉的 3D（那是 plan v12 刻意避開的第二個 WebGL 實例；要的話下一輪談「共用編輯頁那一個實例」）、結果卡片的重新設計（只做工具列／圖例／空狀態）、更多操作種類。

## 5. 設計

### 5.1 結構預覽：可換視角、拖切片、標出每個變數改哪裡

`StructurePicker.tsx` 拆成 `StructurePicker`（下拉＋一句尺寸）與 `StructPreview`：

- **視角**：Segmented「自動｜XY｜XZ｜YZ」。自動＝`autoAxis(box)`（和結果卡片同一規則）。切換時切片位置各軸各記一份（`atBy`），預設外框中點。
- **切片**：antd `Slider`，範圍＝結構外框在法線軸上的 `[lo, hi]`，標「切片 z = 25 · 14～37」。片由 `slabOf(ed.orig, ed.active, axis, at)` 來（parked／live 都行）。
- **大小**：倍率＝`min(8, 舞台寬／裁切寬, 舞台高／裁切高)`，畫出來就是 1:1 顯示，標籤字不會被縮小。舞台寬用 `ResizeObserver` 量（欄寬拖了跟著變），高度可拖（§5.6）。
- **標記**（`drawMarks`，畫在疊在上面的第二張 canvas，同樣的 W×H 與 CSS 大小所以對得準）：每個變數用它的類別色（`CATEGORY[k]`，和卡片色帶、組合表的點、結果卡的 chip 同色）；滑過卡片該標記加粗。
  - `cd`：沿切面內的軸畫雙箭頭＋「寬度 ↔／↕」；
  - `push`／`level`／`taper`：那一面畫粗線，`push`／`level` 加朝外／朝內的箭頭，標「長／縮」「方頭到」「側壁斜度」；
  - `round`：頂端（體素 y 小的一側）兩角畫圓弧（只在 y 在切面內時）；
  - `dilate`：外框外 5 px 的虛線；`translate`：沿軸的雙向箭頭；`defect`：以 `center`（0～1）×外框算位置、`size` 算大小的半透明方塊。
  - 畫不出來（軸垂直於切面）：外框虛線＋圖下一行橘字「PolySi1_D：沿 z，垂直於這個切面（換 XZ 或 YZ 看）」。
  - 標籤：白底藥丸，撞到就往下挪 16 px，夾在畫布內。
- **「在 3D 看」**：`onOpenStructure` → `index.tsx` 的 `pendingFocus` 從 `boolean` 改成 `false | 'diff' | BBox`；帶 `ed.selBox` 切到編輯頁後 `View3DHandle.focusBox(box)`（和「對準差異」同一條路）。
- 圖例一行：藍＝選到的結構、淡＝其他材質、XY 截面、彩色＝各變數會改的地方。

### 5.2 變數卡：一句話、操作可直接換、細節不收起來

`FactorCard.tsx` 重寫；操作的中繼資料抽到 `factorMeta.tsx`（`OP_SHORT` 一句白話、`OpGlyph` 線條小圖示、`templateFor(ed, op)` 預設固定欄位、`newFactor`、`switchOp`、`opsFor(kind)`）。

- 標題列：色帶改成「色塊數字」（1、2…，和預覽標記同色）＋名稱（直接改）＋ id 灰字（點了改）＋重新量／刪除（滑過才浮出）。
- 一句話：「對 **Poly-Si 1** 的［⌒ 圓頭半徑 ▾］· 現在是方角（0）ⓘ」。［▾］是 `Dropdown`，列出這種材質適合的操作（圖示＋名稱＋一句話，目前的那個反白）；換了就 `switchOp`：結構不變、名稱若自訂過留著、固定欄位與水平換成新操作的預設（水平的意義變了，不硬換算）。
- 第二行：`OP_SHORT[op]`（「頂端兩個角改成圓角」）。
- 「要試的值」（§5.3）。
- 「細節」：不再折起來，一列一個——沿哪個軸、哪邊不動（中心（兩側對稱）／z 小端／z 大端）、哪一面（`FacePicker`）、相對於（`level` 的參照結構＋它的頂／底）、哪面側壁／高度軸／要變的是（`taper`）、要變的是／形狀／位置／大小／材質（`defect`）、碰到別的材質（擋住／穿過去）、單位（nm／格，換單位時水平照格數換算）。
- 「加一個變數」：`AddFactorButton`＝同一個操作選單；選了就加進去（`newFactor`：預設欄位＋`presetLevels` 的第一組），不再有獨立的新增表單。

### 5.3 要試的值：chip 可點著改、快速產生三格、預設只是填格

`LevelsEditor.tsx` 重寫，props 不變（`f, levels, problems, nm, onChange`）：

- 標題列：「要試的值 · 3 個 → 3 個 split · 清空」；右邊「絕對｜相對」＋ⓘ（只是換寫法，實際改幾格不變；絕對＝寫改完的值、相對＝寫和現在差多少）。標稱量不到的操作（移動、斜度、缺陷大小）不顯示。
- chips：`<button>`，主字＋小字（絕對：「+2 格」；相對：「→ 改完的值」；對照組寫「對照組」）；點一下＝`Popover`（InputNumber、刪掉、確定），✕ 直接刪；有問題的紅（tooltip 寫原因）。最後一顆「+」才打開語法輸入框（`16, 18, 20`、`±2 step 1`、`nominal ±10%`），placeholder 與錯誤訊息同 v12。
- 快速產生：「起始／間距／個數」三個 `InputNumber`（前綴標籤）＋「套用」（和現有相同時顯示「已套用」反灰）；下一行預覽「→ 1、2、3 nm · 現在 0 nm」。
- 預設：`presetLevels` 的按鈕（±0.5 nm（±1 格）、±1 nm、±10%、2、4、6 格…）改成「把三格填好並套用（取代）」；多一顆「+ 對照組」把現在的值加進去。

### 5.4 組合表：狀態欄寫清楚、「範圍太大」改成有原因的「未試算」

- `TRIAL_CAP` 3 M → 8 M 格（Worker 裡跑、一次一個，`data` 最多 8 MB 一次傳回，可接受）。
- 表頭：「會改幾格 ≈」（tooltip：估計和起點不同的格數，在背景逐列試算）、「被擋」（tooltip）、「狀態」。
- 狀態欄只會是四種藥丸：綠「✓ 可產生」、灰「對照組」（tooltip：每個變數都等於現在的值）、橘「可產生 · 未試算」（tooltip：動到的範圍超過 8 百萬格，試算先略過；按產生時照樣會完整算）、紅「無效原因」（去掉「變數名：」前綴，tooltip 全文）。
- 表尾：有無效或未試算時各一句總結（「2 個組合沒估「會改幾格」：動到的範圍超過 8 百萬格，試算略過；產生不受影響」）。
- 組合方式三顆按鈕下面一句說明（逐一掃描／全因子／手動勾選各一句）。
- 「標稱」改叫「現值」（和卡片的「現在 …」一致）。

### 5.5 視覺系統：色票、面、藥丸、空狀態

`styles.css` 舊的設計區規則整段刪掉重寫；`:root` 加 `--lab-*`（底 `#f3f5f9`、墨 `#0f172a`、線 `#e3e7ee`、面 `#f8fafc`、ok／bad／big 的底與字）、`--radius-xl: 12px`、兩層陰影。

- 設計欄 440 px、白底；段落標題 14 px／600，步驟數字 24 px（做到那步實心藍＋光暈、做完綠底打勾）；標題下一句摘要「Poly-Si 1 · 2 個變數 · 9 個 split」。
- 面：預覽與變數卡是主要的面（圓角 12、淺陰影、滑過微浮起）；變數卡 `inset 4px` 色帶、`color-mix` 讓 chip 的底與字跟著變數色。
- 組合表：藥丸四色（見 §5.4）；表尾總結。
- 產生：黏底、半透明白＋模糊、按鈕 42 px。
- 結果區：工具列左邊「結果」標題與篩選、右邊動作；圖例改成三個小項＋提示；空狀態改成一張卡「三步做一組實驗」（① 選結構 ② 加變數、填要試的值 ③ 看組合，按產生）。結果卡片圓角 12、滑過浮起。
- `prefers-reduced-motion` 時關掉過渡與浮起。

### 5.6 可拖拉的盤面：設計欄寬度、預覽高度

## 9. 風險與對策

| 風險 | 對策 |
| --- | --- |
| 標記畫在 2D 截面上，使用者還是想轉 3D | 先用「三個視角＋切片＋提示換視角」補；「在 3D 看」一鍵到編輯頁對準結構。真要在設計區裡轉，下一輪談共用編輯頁那一個 WebGL 實例（不新開 context） |
| `color-mix()` 舊瀏覽器不支援 | 目標是 Chromium／Safari 16.2+；chip 退化成無底色但仍可讀（字色 `var(--fc)` 前仍有 antd 預設） |
| 試算上限 8 M 讓大模型的試算變慢（每列最多 8 MB 傳回） | 仍是一次一個、可取消；`cap` 只影響估計；超過 8 M 的照樣標「未試算」 |
| 操作換了之後水平直接換成預設，使用者的值沒了 | 水平的單位與意義隨操作變（半徑 vs 寬度），硬換算會給錯的值；選單上「目前」反白、換錯再換回來就是原預設；名稱與結構留著 |
| 預設改成「取代」，和 v12「加到現有」的習慣不同 | 按鈕 tooltip 寫「填進上面三格並套用」；「+ 對照組」保留「加一個」的路徑；chip 可以逐顆改 |
| 設計欄拖太寬把結果區擠掉 | `max-width: calc(100vw − 420px)`＋上限 760 |
| e2e 選擇器跟著 UI 改，之後再改 UI 又要改 | 選擇器盡量用 aria-label／角色（「加一個水平」「輸入水平清單」）而不是 class |
